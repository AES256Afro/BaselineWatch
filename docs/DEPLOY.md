# BaselineWatch on cybercard.net

*Written 2026-10-14 as a plan; rewritten 2026-10-15 after the switch, as a description of what
runs and how to change it; updated 2026-10-16 when the app moved under BoxPilot.*

cybercard.net is BaselineWatch's public home: a read-only information, learning and teaching
site with no private data. Until 2026-10-15 the domain served the FinancialAuthority demo from
GitHub Pages; it now serves BaselineWatch from BigBox through a Cloudflare Tunnel. Since
2026-10-16 the app is one BoxPilot installed from its catalog, so BoxPilot installs, updates,
backs up and restores it like any other app on the box.

## What is there

| Piece | State since 2026-10-16 |
| --- | --- |
| App | BaselineWatch installed from the BoxPilot catalog on BigBox: container `bp-baselinewatch` from `ghcr.io/aes256afro/baselinewatch:<version>`, project files and data under `/var/lib/boxpilot-managed/catalog/baselinewatch/` (`compose.yaml`, `.env`, `boxpilot.json`, `data/`), port 8790 on loopback and the LAN. Settings live on the app's card in BoxPilot. |
| Tunnel | Cloudflare Tunnel named `Baseline Watch`, dashboard-managed, run by BoxPilot's Cloudflare Tunnel app (container `bp-cloudflared`, host network). Routes: `cybercard.net` and `www.cybercard.net` → `http://127.0.0.1:8790`. |
| DNS in Cloudflare | Proxied `CNAME` records for the apex and `www` to the tunnel, created by the tunnel's routes. The old GitHub Pages `A` records and the `www` CNAME are gone. `_dmarc` TXT stays. |
| Zone settings | Always Use HTTPS on. Encryption mode left at Cloudflare's Automatic (reads "Full"); tunnel traffic does not use it, cloudflared speaks plain HTTP to the container on loopback. Redirect rule 1 "Redirect from WWW to root" active (`www` → apex); redirect rule 2 "cybercard.net to rustyschool.com" **disabled, not deleted**: re-enabling it sends the whole site to rustyschool.com. |
| Backups | BoxPilot's per-app backup from the card: the Compose project, `.env` and the `data` volume, archived under `/var/lib/boxpilot-managed/backups/catalog` and copied off the box with the rest of BoxPilot's backups. |
| Old instance | Gone. The hand-run compose project in `/opt/baselinewatch` (compose file, `.env`, `data/`) was stopped for the move and removed the same day once the managed instance was confirmed, with the images before 0.17.0. |
| Demo | GitHub Pages for `AES256Afro/financialauthority-demo-cybercard` has no custom domain any more; `FinancialAuthority/scripts/publish-demo.sh` and `docs/DEMO.md` name only demo.aes256afro.com. |
| Categorisation | Requested 2026-10-15 in Security Center → Investigate: Education and Information Security. Cloudflare reviews it. |

## How it is set up

### 1. The code and the image (from the development machine)

```bash
git push -u origin main && git tag v0.17.0 && git push origin v0.17.0
```

CI (`.github/workflows/ci.yml`) runs the checks, boots the container and on a tag pushes
`ghcr.io/aes256afro/baselinewatch:<version>`, signed with cosign and carrying an SBOM and
provenance. The package is public, so BigBox pulls without a token.

### 2. The catalog entry (AES256Afro/BoxPilot)

`boxpilot/baselinewatch.yaml` in this repo is the manifest; its copy is
`catalog/baselinewatch.yaml` in BoxPilot, merged on 2026-10-15
([AES256Afro/BoxPilot#472](https://github.com/AES256Afro/BoxPilot/pull/472)) and shipped in
BoxPilot 1.186.0. The catalog travels inside BoxPilot, so an install needs BoxPilot at that
version or later (System page → update).

### 3. Running it on BigBox (BoxPilot, signed in)

Apps → Add an app → BaselineWatch → Install, with:

| Setting | Value for cybercard.net |
| --- | --- |
| Address people use (`BW_BASE_URL`) | `https://cybercard.net` |
| Time zone (`TZ`) | `America/New_York` |
| Anyone on the network can read (`BW_PUBLIC_READ`) | on |
| Owner password, Session signing secret | generated by BoxPilot; the card's Sign in shows the password |
| Web UI port | 8790, which is where the tunnel's routes point |
| Look, Colours, digest, notification URL, NVD key, local model | as you like; the defaults are Console, System, daily at 07:00, none |

BoxPilot writes `compose.yaml` and `.env` under `/var/lib/boxpilot-managed/catalog/baselinewatch/`,
creates `data/` owned by the image's user (`node`, uid 1000) and starts the container. The first
fetch of each standard, ten seconds after start, loads its published history, so a fresh install
needs no backfill. A setting changed on the card is written to `.env` and the container is
recreated; the data directory stays.

The project directory is root-only, so one-off commands go through docker, which the `bigbox`
user may run without sudo:

```bash
docker exec bp-baselinewatch node --disable-warning=ExperimentalWarning src/cli.ts backfill nist-sp-800-53
```

```bash
docker exec bp-baselinewatch node --disable-warning=ExperimentalWarning src/cli.ts relink all
```

#### The move from the compose instance (2026-10-16)

The data came across from the hand-run instance in `/opt/baselinewatch` without a backfill:

```bash
cd /opt/baselinewatch && docker compose down
```

frees port 8790 and closes the database cleanly (the WAL folds into `baselinewatch.db`). After the
catalog install came up, the new container was stopped and its empty data directory replaced
through a helper container, since the managed directory is not readable by the ssh user:

```bash
docker stop bp-baselinewatch && docker run --rm --user 0 --entrypoint sh -v /var/lib/boxpilot-managed/catalog/baselinewatch/data:/dst -v /opt/baselinewatch/data:/src:ro ghcr.io/aes256afro/baselinewatch:0.17.0 -c 'rm -rf /dst/* && cp -a /src/. /dst/ && chown -R 1000:1000 /dst' && docker start bp-baselinewatch
```

`/health` on the managed container then reported the old instance's counts (sources 44, items
3698, vulns 21675) and cybercard.net answered through the tunnel again. The same recipe restores
a copy of `data/` taken from anywhere else. `/opt/baselinewatch` was then emptied as `bigbox` and
its entry in root-owned `/opt` removed through the same kind of helper container (`rmdir` only),
and the unused images were removed with `docker rmi`.

### 4. The tunnel (BoxPilot and the Cloudflare dashboard)

A tunnel made in the dashboard (Networking → Tunnels → Create, token copied into BoxPilot → Apps →
Cloudflare Tunnel → Install) runs as BoxPilot's app. Its public hostnames are routes on the
tunnel in the dashboard ("Add route" → "Published application"): subdomain empty and `www`,
domain `cybercard.net`, service `http://127.0.0.1:8790`. Each route creates its proxied DNS record.

BoxPilot's own Tunnel tab (Connect with an API token, then Publish) was not used for this site:
its Publish takes only an app BoxPilot installed and a single DNS label, never the bare domain
(BoxPilot ADR-011). Now that BaselineWatch is a BoxPilot app it would do for a subdomain of
another zone.

### 5. DNS and the zone (Cloudflare dashboard)

The GitHub Pages `A` records and the `www` CNAME were deleted by hand before the tunnel routes
were added, which is why the routes could create their CNAMEs. Then Always Use HTTPS was turned
on, and the dormant redirect to rustyschool.com, which only fired once the zone became proxied,
was disabled.

### 6. The demo

```bash
gh api -X PUT repos/AES256Afro/financialauthority-demo-cybercard/pages -f cname=
```

and the two FinancialAuthority files edited; the repo holds only built files and still exists.

### 7. Categorisation

Security Center → Investigate → `cybercard.net` → Add category → Education and Information
Security → Submit. The guide is
https://developers.cloudflare.com/security-center/investigate/change-categorization/.

## Upgrading

A release is a tag; CI publishes the image. From there the version reaches BigBox through the
catalog: BoxPilot's daily catalog-updates workflow sees the new tag and opens the bump pull
request against `catalog/baselinewatch.yaml` (or bump `image.reference` and `image.version`
there by hand), the next BoxPilot release carries it, BigBox takes that release from the System
page, and BaselineWatch's card then offers the newer image. BoxPilot pulls it and recreates the
container; the data directory carries over and migrations run at start. Check with
`https://cybercard.net/health`, which reports the running version.

After a version that adds a standard, the standard loads itself on its first scheduled fetch; to
load it at once, run the `backfill` command above with the source id. Package advisories start
once a package is on the watchlist.

## Backups

On the app's card: Back up now, or a schedule under System → Schedules. Each archive holds the
Compose project, `.env` (with the generated secrets) and `data/`, and the card offers each recorded
backup for restore, which stops the app, puts the volume back and starts it. BoxPilot's off-box
copies (backup drive, SSH, cloud) carry these archives with everything else. A machine snapshot
reinstalls the app with its settings but not its data; the app backup is what restores the data.

## Checks

```bash
curl -sI https://cybercard.net/ | grep -i "^HTTP\|content-security-policy\|strict-transport"
```

The answer is `200` with the app's `Content-Security-Policy` header, and its
`Strict-Transport-Security` header once the address on the card is an `https://` one;
`https://cybercard.net/health` reports the running version and the database counts, and
`https://cybercard.net/login` takes the owner password from the card. A browser that visited
the domain while the rustyschool redirect was active may replay the cached 301 until its cache
is cleared; a private window shows the live answer.
