Do it by hand macOS

Pick a platform: Windows 11 · macOS · iPhone and iPad · Android · Linux · Router · Pi-hole and AdGuard Home. Each section is one thing the scan checks, how to do it yourself, how to prove it, and why.

1. Filter DNS for every app on this Mac

  1. Decide which resolver. AdGuard DNS, NextDNS and Mullvad each publish a filtering resolver; a Pi-hole or AdGuard Home on your network is the same thing for every device. If you use a VPN or iCloud Private Relay, it brings its own DNS and wins; set the filter there instead.
    Why: a browser blocker protects one browser; the system resolver covers every app that uses it, which is most of them. Apps with their own resolver still bypass it.
  2. Install the resolver's profile. Open the resolver's setup page, choose the filtering server, download the configuration profile, then System Settings, General, Device Management: review the provider and the DNS servers it names, then install. AdGuard's instructions · NextDNS's. Stop if the profile's details do not match the provider's page.
  3. Prove it. In Terminal: scutil --dns | head -20 shows the resolver in use; dig +short ad.doubleclick.net returns 0.0.0.0 or nothing when the filter answers. Then run the browser check here: the resolver row names the provider.
  4. Check it stays. A VPN or a profile change can replace it. The Mac's device script reports the resolver every time it runs.

2. A content blocker in the browser

  1. Install uBlock Origin in Firefox, or a content blocker in Safari (Safari extensions use the content-blocker API; uBlock Origin Lite is the Chrome build since Chrome's extension change). uBlock Origin
  2. Prove it. Run the browser check: ad hiding should show baits hidden and ad requests a load difference. A blocker that hides nothing here may still block requests; look at its request log.

3. The Mac's own firewall

  1. Turn it on. System Settings, Network, Firewall: on, with stealth mode on and incoming connections blocked for the apps you do not expect to listen. Apple, "Block connections to your Mac with a firewall"
  2. Prove it. /usr/libexec/ApplicationFirewall/socketfilterfw --getglobalstate --getstealthmode prints both as enabled. For the packet filter underneath: sudo pfctl -s info.
    Why: the application firewall stops a program that was not expected to listen from accepting connections from the LAN, which is where a compromised device next door would come from.

4. Lockdown Mode, if you are a likely target

  1. System Settings, Privacy & Security, Lockdown Mode. It limits what an attack can do if one gets through: message attachments, web technologies, wired accessories, configuration profiles. It is for people who may be targeted by mercenary spyware, and it cannot be managed by MDM. Apple, "About Lockdown Mode"

5. Take away the advertising identifier

  1. System Settings, Privacy & Security, Apple Advertising: turn off Personalized Ads. On iPhone also Tracking: Allow Apps to Request to Track, off.
    Why: targeted ads are how a target is picked; without the identifier the ad network has less to aim with. It does not remove ads.

6. If you need to know about the past

  1. Run the Mac device script for the browser traces; for a phone, Amnesty's Mobile Verification Toolkit reads a backup against its indicators. MVT documentation. A clean result is not a clean bill of health; a concrete reason to think you were targeted is a reason to call a helpline, not to run a tool.

Router, any platform

  1. Open the admin page (the gateway address the router check names, usually 192.168.1.1 or 192.168.0.1) and change the password printed on the device if it is still in use.
  2. DNS. Set the DHCP DNS to your filtering resolver so every device gets it; leave the router's own resolver out.
  3. UPnP off, unless something you run needs it; then read the mappings table once a month.
  4. Remote management off on the WAN side; admin over HTTPS only.
  5. Firmware. Note the version; the router check compares it with the CVE database and alerts on a KEV entry.
  6. Prove it. The router check reads the DHCP DNS, the mappings and the WAN exposure from here; the firewall check reads what the internet sees.

Other platforms

Windows 11
Settings, Network, adapter, DNS server assignment: the filtering addresses with DNS over HTTPS on; prove with Get-DnsClientServerAddress and Get-NetFirewallProfile.
iPhone
The resolver's profile under Settings, General, VPN & Device Management; or Settings, Wi-Fi, ⓘ, Configure DNS.
Android 9+
Settings, Network & internet, Private DNS, the provider hostname (Samsung: Settings, Connections, More connection settings, Private DNS).
Linux
resolvectl dns and resolvectl status; nft list ruleset or ufw status.

Limits

DNS filtering cannot remove ads from Instagram, Facebook, TikTok or YouTube: those come from the same servers as the content. A browser test sees one browser. None of this says whether anything already happened.
