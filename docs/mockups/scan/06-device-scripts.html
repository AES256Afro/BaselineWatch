Device scripts what a browser cannot see

A web page sees one browser. These scripts run on the device and read what the apps actually use: the system resolver, the hosts file, the firewall's state, the DNS cache and the browsers' history against the indicator list. They are read-only, need no administrator rights for the default checks, make no network requests, and change nothing. Every line is in the file you download; read it first.

PS
Windows · bw-scan.ps1 PowerShell 5.1 or 7
Reads: resolver per adapter and DoH settings; the hosts file; Windows Firewall profile state and inbound default; the DNS client cache against the indicator list; whether DNS-Client event logging is on (off by default, so the past is not recorded); browser history and cookie hosts for Edge, Chrome, Brave, Firefox against the list; per-user COM registrations the documented campaign used to persist; the advertising ID setting.
  • SHA-256 3f6a…c21e · 14 KB · signed with the instance's key (fingerprint on the Sources page)
  • Run: powershell -ExecutionPolicy Bypass -File .\bw-scan.ps1 · about two minutes · close browsers first so their databases are not locked

What a report looks like

bw-scan 1.0 · WORK-LAPTOP · Windows 11 25H2 · 2026-10-19 08:12
resolver      Ethernet: 192.168.8.10 (DHCP) · DoH: not configured
hosts file    81 lines, 0 indicator matches
firewall      Domain on, Private on, Public on · inbound default Block
dns cache     412 entries, 0 indicator matches
dns logging   Microsoft-Windows-DNS-Client/Operational: OFF (the past is not recorded; see the guide to turn it on)
browsers      Edge 3,210 history rows, Chrome 1,044, Firefox 0 · 0 indicator matches · cookies: 0 matches
persistence   per-user COM registrations: 0 of 2 documented paths present
advertising   ID: disabled
not checked   Brave (not installed) · Vivaldi (not installed)
verdict       no indicator found where it could be looked for; a clean result is not a clean bill of health
paste this report at /scan/devices or keep it with the device's record

Before you run anything

  • Check the SHA-256 against the one shown here; the Sources page has the signing key.
  • Read the file. Every check is a few lines; nothing is obfuscated and nothing is downloaded by the script.
  • A clean result means no known indicator was found where it could be looked for. It is not a clean bill of health.
  • If you have a concrete reason to think you were targeted, use a helpline, not a script: Access Now's Digital Security Helpline, Amnesty's Security Lab.

The indicator list

The scripts carry the adfection list the network check uses: 291 reviewed domains and the IP addresses from the published Candiru and ad-delivered-spyware research. The list is a Register source, so when it changes the scripts are rebuilt and their checksums change with it, and the change is a diff you can read.

Why read the device at all

Where an ad leaves a trace, history alone misses it: cookies, cache and storage keep the hosts an ad frame touched. The resolver and firewall rows say what every app on the device uses, which no browser test can. More
