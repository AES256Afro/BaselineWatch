Why these checks and what each can prove

Ads are a delivery path. The same auction that places a shoe advertisement can place code, and it has: Citizen Lab documented an advertising-technology pipeline that delivered Candiru's spyware through targeted ads. Filtering ad delivery closes that road; it is one road, and the checks here say which roads are closed on this browser, this network and this router, nothing more.

Ads as a delivery path

An ad is content fetched from a third party at the moment the page loads, chosen for you by an auction that knows your identifier, your location and your device. That is also a description of a targeted exploit delivery system, and the research below shows it being used as one. Blocking the request means the code never arrives; hiding the slot means it arrived and was not shown. Ads served from the same domain as the content (Instagram, YouTube, TikTok) are not blocked by any of this, because the content and the ad are the same server.

  • Citizen Lab, "How Discover-Tech turned targeted ads into a pipeline for spyware"
  • Citizen Lab research index

Ad hiding

Content blockers carry generic cosmetic rules that hide any element named like an ad slot. The check plants twenty such names and two neutral ones and reads back which were hidden. It proves a blocker with cosmetic rules is active in this browser. It does not prove requests were stopped (that is the next check), and a blocker that hides nothing here may still block everything, so a zero is "not observed", never "unprotected".

  • uBlock Origin, the blocker whose generic rules these names come from
  • EasyList, the filter list most blockers carry

Ad requests

Request filtering is the control that matters, because the request is what carries a payload. The check loads images whose paths match the common request rules, between control images with identical bytes, on this server and on one cross-site host. A load difference is evidence of request filtering; a timeout is unknown; a page-policy failure is reported as such. No advertising domain is contacted, so the test leaks nothing to an ad network.

Filtering DNS

A browser blocker protects one browser. A filtering resolver answers "no such name" for ad, tracker and malware domains for every app that uses the system DNS, which is most apps on a phone and most on a computer. The browser check can confirm two resolvers by their own self-check endpoints; the network check confirms any resolver by resolving canaries through it from this server. A VPN, iCloud Private Relay or a browser's own DNS-over-HTTPS replaces the system resolver and must be checked where it is set.

  • AdGuard DNS public servers
  • NextDNS self-check
  • Pi-hole documentation

Ad-delivered spyware domains

The research names the domains the delivery pipeline used; the Zero Breach project compiled them, with the indicators from the earlier Candiru reports, into one reviewed list of 291 domains and 111 addresses, exported as DNS and ad blocklists. Adding that list to a filtering resolver blocks the documented infrastructure for every device on the network. The list changes as research is published; this product tracks it as a Register source so a change is a diff with a date, not a surprise.

  • Zero Breach repository (indicator list, blocklist exports, the offline scanner)
  • Citizen Lab, the 2026 report

The router

Every device on the network trusts the router for its address, its DNS and its path out. A router with a known exploited vulnerability on its LAN-side admin page is reachable by any device that joins the network, including a guest's phone; one with remote management open on the WAN side is reachable by everyone. The router check reads the model and firmware the gateway announces and matches them against the CVE database and CISA's KEV, which this product already keeps current by the hour.

  • CISA, Known Exploited Vulnerabilities catalog

UPnP port mappings

Universal Plug and Play lets any program on the LAN ask the router to open a port from the internet to that program, without a password. Games use it; so does anything that wants to be reachable. A mapping to a remote-desktop or file-sharing port is a hole in the firewall that nobody approved. Turning UPnP off removes the mechanism; reading the table once a month catches what it opened.

What the internet sees

Public indexes crawl every address and record what answered. That record is what an attacker reads before touching anything, so the first question about your address is what the index says. The firewall check asks Shodan's free lookup rather than scanning from here, which keeps this product from being the thing that scans you.

  • Shodan InternetDB

DNS bypass and interception

Network-wide filtering only covers devices that use the network's resolver. A device with a hard-coded resolver, or a browser using DNS-over-HTTPS, walks past it unless the router redirects port 53 and blocks the known DoH endpoints. The opposite failure also exists: an ISP or a router that silently redirects every DNS query to itself. The check sends a resolver-identity query straight to a public resolver and reads who actually answered.

  • Pi-hole, forcing all DNS through the resolver

Reading the device itself

Where an ad leaves a trace, history alone misses it: cookies, cache and local storage keep the hosts an ad frame touched. Windows does not record DNS lookups unless its DNS-Client log is turned on, so the past is usually unrecorded; turning it on is the one setting the scripts recommend. A clean result means no known indicator was found where it could be looked for; spyware of this grade is built to defeat exactly this kind of check, so a concrete reason to think you were targeted is a reason to use a helpline.

  • Amnesty International, Mobile Verification Toolkit
  • Access Now Digital Security Helpline
  • Amnesty International Security Lab

Hardening, in order

  1. Filter DNS for every app on the device and, at the router, for every device. Reduces requests to known ad and tracking domains.
  2. Lockdown Mode on iPhone, iPad and Mac for anyone likely to be targeted: limits what an attack can do if one gets through. Apple, About Lockdown Mode
  3. Take away the advertising identifier: changes how a target is picked in the first place.
  4. Look at the past with the device scripts or the Mobile Verification Toolkit; none of the first three says whether anything already happened.
