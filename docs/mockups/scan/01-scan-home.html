Scan ads, DNS, router, firewall

Four short checks with four different eyes. The browser check runs in this tab and sees this browser only. The network, router and firewall checks run from this server, which sits on your LAN, so they see what a web page never can: every device behind the router. Results stay on this instance; nothing is uploaded.

Why scan for ads at all

Advertising networks deliver code to a device the way any other content arrives, and that path has been used to deliver spyware: Citizen Lab documented an ad-tech pipeline that placed Candiru's spyware through targeted ads. Blocking ad delivery closes one road in; it is not proof of safety, and ads served from the same domain as the content are not blocked by any of this. The whole argument, with the sources.

What each eye can and cannot see

Browser
This tab only. Not other apps, not other devices.
Network
Whatever uses the LAN's resolver. A phone on a VPN or a browser on DNS-over-HTTPS bypasses it.
Router
What the router says about itself and what the LAN side exposes.
Firewall
The public address from outside, and the paths out from inside.

The one page with a script

The browser check needs a few lines of script in this tab. Every other page on this site runs with script-src 'none'; the Scan page alone carries its own policy allowing one self-hosted file and the two self-check hosts. No inline script anywhere.
